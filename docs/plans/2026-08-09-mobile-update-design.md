# 移动端版本检查与 Android 官网更新设计

## 目标

将移动端正式版本统一为 `v1.0.0`，由产品官网托管一份固定的更新策略 JSON。App 在启动、恢复前台和用户手动检查时读取策略；Android 官网分发版可下载 APK 并交给系统安装器更新，应用商店版本继续由对应商店完成安装。

## 版本与发布基线

- Flutter/iOS/Android 的正式展示版本统一为 `1.0.0`，Dart UI 显示为 `v1.0.0`。
- Android 构建号使用 `2002`。官网现有内测 APK 已使用 `versionCode=2001`，新包必须递增。
- HarmonyOS 保持 `versionName=1.0.0`、`versionCode=1000000`；其构建号独立于 Android/iOS。
- 官网现有 APK 是 `1.0.0-alpha` 且由 Android Debug 证书签名，不能作为正式包继续发布。正式包必须使用长期保存的 Release 签名；已安装 Debug 内测包的用户需要卸载一次，此后的正式包可覆盖更新。

## 更新策略文件

官网根目录提供 `website/app-update.json`。部署在域名根目录时，固定地址为 `https://<产品官网>/app-update.json`；部署在子路径时由构建参数传入完整地址。

策略按平台分别提供以下字段：

- `latestVersion`：展示版本，例如 `1.0.0`。
- `latestBuild`：用于可靠比较的整数构建号。
- `minimumBuild`：低于此值时必须更新；否则新版本允许稍后处理。
- `releaseNotes`：更新说明。
- `delivery`：`store` 或 `direct`。
- `updateUrl`：应用商店地址，或官网 APK 地址。
- `sha256`：仅 Android 直接下载使用；正式 APK 生成后写入。

策略包含 `schemaVersion`，客户端只接受已知版本、HTTPS 地址、合法整数和受支持的交付方式。服务端文件替换应在新版本已经发布并可下载后进行，并使用短缓存或刷新 CDN 缓存。

## App 更新流程

1. App 首帧完成后检查一次；从后台恢复且距离上次自动检查至少 12 小时时再检查。
2. “我的 → 关于 → 检查更新”始终发起手动检查，不受 12 小时间隔限制。
3. 客户端按当前平台选择策略，以 `latestBuild` 与本地构建号比较。
4. 没有新版本时，手动检查显示“已是最新版本”，自动检查保持安静。
5. 普通更新显示版本和更新说明，允许“稍后”；构建号低于 `minimumBuild` 时仅提供“立即更新”。
6. 检查超时、断网、JSON 无效或服务端错误都不得阻止 App 启动；手动检查显示可理解的错误，自动检查静默失败。

## Android 官网分发版

- 官网版下载 `website/downloads/ZT-Monitor-Android.apk` 对应的 HTTPS 地址。
- 下载完成后先核对策略中的 SHA-256，再调用 Android 系统安装器。
- 系统会校验包名、签名和构建号；安装确认以及“允许从此来源安装”由 Android 控制，App 不承诺静默安装。
- 正式包必须持续使用相同的 Release 密钥和相同 application ID。
- Google Play 分发版不声明 APK 安装权限，也不执行官网 APK 自更新，以避免违反商店政策。官网版与商店版通过分发渠道配置选择不同更新动作。

## iOS 与 HarmonyOS

- iOS 只打开 App Store 或 TestFlight 地址，不下载 IPA，也不自行安装。
- HarmonyOS 打开华为应用市场地址；若后续接入应用市场原生升级能力，保持同一策略模型。
- 在应用商店 ID 尚未配置时，对应平台可检查版本但不得显示不可执行的更新按钮。

## 配置与安全

- 更新策略 URL 是项目控制的固定 HTTPS 地址，通过构建参数提供默认值或覆盖值，不能从用户可编辑的 Hub URL 派生。
- APK 下载只允许 HTTPS，并限制到策略地址同源或显式允许的产品官网域名。
- Release keystore、口令和 `key.properties` 不进入 Git；仓库只提交示例配置和忽略规则。
- 当前 HarmonyOS 构建配置含明文签名材料路径与口令，属于独立安全整改项；本功能不复制或扩散这些秘密。

## 测试与验收

- 单元测试覆盖版本比较、平台策略解析、普通/强制更新判定、无效 JSON、超时和 12 小时节流。
- Widget 测试覆盖“检查更新”行、最新版本提示、普通更新弹窗和强制更新弹窗。
- Android 原生测试或可重复人工步骤覆盖：下载失败、SHA 不匹配、未知来源授权、系统安装确认、签名不一致和成功覆盖安装。
- 校验官网 JSON 可解析，APK 的真实版本、构建号、签名和 SHA-256 与策略完全一致。
- 运行 Flutter 静态检查与测试；仓库根目录运行 `npm run verify`，确保移动端改动没有影响桌面端。
